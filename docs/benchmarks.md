## Takeaways

- Prophet: the 28-worker pool gives 10.7x the serial throughput; keep fits on the CPU pool. Per-fit time rises inside the pool (0.094 s to 0.242 s) because of all-core clocks, E-cores and CmdStan's per-fit subprocess and CSV I/O, so batch several fits per task where possible.
- NeuralProphet single small fit: CPU is faster (0.64 s CPU vs 1.21 s GPU); use the GPU only for batched ensembles or global models.
- Batched least squares: GPU float32 peaks at 7x the CPU float64 rate; LPPLS grids go to the GPU with CPU float64 refinement.
- FP64 on this GPU is a small fraction of FP32; do not port float64 kernels to the GPU as-is.
